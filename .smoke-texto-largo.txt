Un array en JavaScript es una lista ordenada de valores. Cada elemento ocupa una posición llamada índice, y el primer índice es siempre cero, nunca uno. Para leer un elemento se escribe el nombre del array y el índice entre corchetes. La propiedad length devuelve cuántos elementos tiene el array y se actualiza sola cuando el array cambia de tamaño. Si se pide un índice que no existe, el resultado es undefined en vez de un error, algo que suele confundir a quien viene de otros lenguajes. Un array puede guardar cualquier tipo de valor, incluidos otros arrays, y por eso se usa tanto para listas de datos como para matrices.

El método push agrega uno o más elementos al final del array y devuelve la nueva longitud. Su hermano pop quita el último elemento y lo devuelve, así que push y pop juntos funcionan como una pila. shift quita el primer elemento y unshift agrega elementos al principio; estas dos operaciones son más costosas porque obligan a reacomodar todos los índices. Los cuatro modifican el array original, algo importante de recordar antes de guardarlo en otro lado. Para buscar sin modificar, indexOf devuelve la posición de un valor o menos uno cuando no está.

map recorre el array y devuelve un array nuevo del mismo largo, con cada elemento transformado por la función que se le pasa. filter devuelve un array nuevo solo con los elementos que cumplen una condición. reduce recorre el array acumulando un único resultado, que puede ser un número, un objeto o incluso otro array. Los tres reciben una función como argumento y no modifican el array original, lo que se conoce como programación funcional. Encadenarlos permite escribir transformaciones complejas en una sola expresión legible.

Un objeto es una colección de pares clave-valor. Se accede al valor con el nombre de la clave usando punto o corchetes, pero los corchetes son obligatorios cuando la clave está guardada en una variable. Object.keys devuelve un array con las claves y Object.values un array con los valores, mientras que Object.entries devuelve pares de clave y valor. Para saber si una clave existe conviene usar el operador in en lugar de comparar contra undefined. Si se lee una clave que no existe, el resultado es undefined y no un error.

La desestructuración permite extraer valores de arrays y objetos en una sola línea. Con objetos se elige el valor por nombre de clave, y se puede renombrar con dos puntos o poner un valor por defecto con el signo igual. Con arrays se elige por posición y se pueden saltear elementos dejando espacios entre comas. La desestructuración anidada llega a valores internos sin repetir el camino completo. También funciona en los parámetros de una función, que es donde más se usa en la práctica.

Una función es un bloque de código reutilizable que recibe parámetros y devuelve un valor. Si no se escribe return, el resultado es undefined, aunque la función haya hecho otras cosas. Los parámetros pueden tener valores por defecto, que se usan cuando el argumento llega vacío o no llega. El operador de propagación junta los argumentos sobrantes en un array cuando se usa en la lista de parámetros. Las funciones son valores: se pueden guardar en variables, pasar como argumento y devolver desde otra función.

Un closure es la combinación de una función y el entorno donde fue creada. Gracias a los closures, una función interna sigue viendo las variables de la función externa aunque esa función ya haya terminado de ejecutarse. Con eso se construyen contadores privados, fábricas de funciones y callbacks que recuerdan un valor. Cada llamada a la función externa crea un closure nuevo y aislado, así que dos contadores creados igual no comparten estado. Entender los closures es la base para entender los hooks y los manejadores de eventos.

El alcance o scope define dónde vive una variable. Con let y const la variable vive en el bloque donde fue declarada, mientras que var vive en toda la función. El hoisting hace que las declaraciones se muevan al principio, pero solo las funciones completas quedan disponibles antes de su línea; las variables quedan en una zona muerta hasta que se ejecuta su declaración. Por eso llamar a una función declarada más abajo funciona, y usar una variable declarada con let más abajo tira un error de referencia.

El valor de this depende de cómo se llama la función, no de dónde fue escrita. En una llamada normal this es undefined en modo estricto, y dentro de un objeto apunta al objeto. Con las funciones flecha, this se hereda del contexto donde se escribió la flecha y no se puede cambiar. Los métodos call, apply y bind permiten fijar this a mano. Confundir el this de un callback es una de las causas más comunes de errores en manejadores de eventos.

Una promesa representa un valor que todavía no está disponible. Tiene tres estados posibles: pendiente, resuelta o rechazada, y una vez que pasa a resuelta o rechazada ya no cambia. Se consume con then para el caso exitoso y catch para el error, y el método finally corre siempre. Las promesas permiten encadenar operaciones sin anidar callbacks, que era el problema conocido como infierno de callbacks. Promise.all espera a que terminen todas y falla si alguna falla, mientras que Promise.allSettled espera a todas sin importar el resultado.

async y await son azúcar sintáctica sobre las promesas. Una función marcada como async siempre devuelve una promesa, y dentro de ella await pausa la ejecución hasta que la promesa se resuelve, sin bloquear el hilo. El código queda con la forma de una lectura secuencial aunque por debajo siga siendo asíncrono. Si la promesa se rechaza, el await lanza una excepción que se atrapa con try/catch. Se pueden lanzar varios await en paralelo creando primero las promesas y esperándolas después.

El manejo de errores se hace con try, catch y finally. El bloque try contiene el código que puede fallar, catch recibe el error y finally corre siempre, haya error o no. Es importante distinguir entre errores de programación, que conviene arreglar, y errores esperables, como una respuesta de red que falla, que se manejan con gracia. Un catch vacío esconde el problema y hace imposible diagnosticar. Se puede lanzar un error propio con throw cuando una condición invalida el resto de la operación.

Los módulos permiten dividir el código en archivos. La palabra export pone una función, una constante o un tipo a disposición de otros archivos, y import los trae. Por defecto cada módulo tiene su propio alcance, así que nada se filtra hacia afuera sin exportarlo. Se puede exportar por nombre, que permite varios por archivo, o por defecto, que permite uno solo. Los imports se resuelven una vez y el módulo se evalúa una sola vez, aunque se importe desde diez lugares distintos.

Una clase es una plantilla para crear objetos. El constructor corre al crear la instancia y ahí se inicializan los campos. Los métodos viven en el prototipo, así que todas las instancias los comparten en vez de copiarlos. La palabra extends permite heredar de otra clase y super llama al constructor de la clase madre. En JavaScript la herencia real es prototípica y la palabra class es una forma más clara de escribirla, no un mecanismo distinto.

Trabajar de forma inmutable significa crear un valor nuevo en lugar de modificar el existente. Esto evita efectos colaterales difíciles de rastrear, sobre todo cuando el mismo objeto se pasa a varias funciones. En arrays se usan métodos como map y filter, y en objetos el operador de propagación para copiar y cambiar una sola clave. Una copia superficial no alcanza cuando hay objetos anidados, porque las referencias internas siguen siendo las mismas. En frameworks de interfaz, la comparación por referencia es la que decide si hay que volver a dibujar.

Para recorrer colecciones hay varias opciones. El bucle for clásico controla el índice y permite cortar antes de tiempo. for of recorre los valores de un array o de cualquier objeto iterable, y es el más claro cuando no se necesita el índice. for in recorre las claves, y en arrays conviene evitarlo porque incluye propiedades heredadas en forma de texto. Los métodos forEach y map también recorren, pero no se pueden cortar con break, así que no sirven para búsquedas con salida temprana.

JSON es el formato de intercambio de datos más usado en la web. JSON.stringify convierte un valor en texto y JSON.parse hace el camino inverso. Las claves siempre son cadenas entre comillas dobles y los valores admiten objetos, arrays, números, booleanos, cadenas y null. Las funciones y los valores undefined no tienen representación y se descartan al convertir. Un JSON mal formado hace que parse lance una excepción, así que conviene envolverlo en try/catch cuando el texto viene de afuera.

Map y Set son colecciones pensadas para casos que el objeto y el array resuelven mal. Un Map guarda pares clave-valor donde la clave puede ser cualquier valor, incluido un objeto, y conserva el orden de inserción. Un Set guarda valores únicos y resuelve la pertenencia en tiempo constante, lo que sirve para eliminar duplicados de un array. Los dos tienen size en lugar de length y métodos propios como has, get, set, add y delete. A diferencia del objeto, no heredan propiedades del prototipo, así que las claves son exactamente las que se cargaron.

Una función pura devuelve siempre lo mismo para los mismos argumentos y no modifica nada fuera de sí misma. Las funciones puras son fáciles de probar y de razonar, porque no dependen del estado del programa ni del momento en que se llaman. Los efectos colaterales, como escribir en pantalla, pedir datos por red o modificar una variable global, se aíslan en los bordes del sistema. Separar el cálculo de los efectos es la razón por la que los componentes de interfaz se dividen en partes presentacionales y partes con lógica.
